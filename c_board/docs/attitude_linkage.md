# 姿态与双 GM6020 联动修改说明

电机相关代码已全部合并到 `applications/motor_task.cpp`：包括拨杆档位、联动目标、手动拖动、R 标复位、位置/速度双环 PID 和 CAN 收发。之前新增的 `motor_pid.hpp` 和 `attitude_linkage.hpp` 已移除。IMU 采集保留在原来的 `applications/imu_task.cpp`，通过变量把姿态提供给电机任务。A 保持电机 ID 2，B 保持电机 ID 1。

## 初学时先看哪里

先在 `motor_task.cpp` 搜索 `motor_task`，看其中的 `for (;;)`: 它的意思是一直重复执行控制。中文注释把主循环分成六步，不必一开始就研究前面所有的函数。

先理解下面这条关系：

```text
C 板/拨杆/手动转动 -> 两台目标角度 -> 位置环算目标速度 -> 速度环算力矩 -> CAN 发给电机
```

“目标角度”是希望电机到哪里，“反馈角度”是编码器读到的实际位置。两者相减就是位置误差。`linkage.update(...)` 负责算目标，`pid_a.update(...)` / `pid_b.update(...)` 负责把目标和反馈换算成力矩。前面的代码只是这些函数的具体实现，现在都在同一个文件里。

文件开头标注“一、参数”“二、双环 PID”“三、联动逻辑”“四、电机任务”。调整 PID 时主要看顶部 `kPositionKp、kSpeedKp、kSpeedKi`。`MOTOR_TASK_TEST` 是电脑回归测试的开关，正常 STM32 编译不用设置它。

## 原代码的问题

1. 原来的 `Kp * 位置误差 - Kd * 实际速度` 是 PD，不是完整 PID。当前主要问题是联动状态和参考点管理，增加 Ki 不能解决这些问题。
2. `yaw_step < 0.005 rad` 是单周期判断。2 ms 周期下，转速低于 2.5 rad/s（约 143°/s）都可能被当作静止，导致正常跟随被误认为手动拖动。
3. 只接受 `motor_step > 0.003 rad`，意味着慢于约 86°/s 的拖动容易漏检；即使进入手动状态，小步进仍被丢弃。
4. 左档直接改变 `ratio * (yaw - yaw_reference)`，会重新缩放历史偏转，造成 B 的目标突跳。
5. 上档只是采集当前位置，并没有驱动到机械 R 标。手动联动参考点与机械零点必须独立保存。

## 先做一次机械标定

代码在每次程序重新启动后标定，不写 Flash。按 C 板 RESET 键可以代替断电重启。步骤如下：

1. 遥控器右拨杆置下档，确认两台电机无主动保持力矩，再手动将 C 板与两台电机的三个 R 标方向对齐。
2. 保持右下档和三个 R 标对齐，按一次 C 板 RESET 键；也可以保持对齐后断电重新上电。
3. 重启后保持不动至少 2 秒。电机任务启动后，在遥控、两电机反馈和 IMU 任务数据均在线时，下档连续静止 500 ms，保存 `yaw_R、angle_A_R、angle_B_R`。
4. 然后切右中档测试联动，切右上档测试复位。

程序无法自动识别 R 标。如果首次静止采样时没有实际对齐，复位方向就会错误；应右下档、重新对齐、按 RESET 并保持不动，重新标定。标定后再切下档不会覆盖机械零点。右拨杆上档只是使用已记录的零点复位，不会重启程序或重新标定。未完成标定时，中档可以联动，但上档保持零力矩。

这里假设两台电机定子固定在标定时的基座上，C 板绕共同 yaw 轴独立转动。若定子会随 C 板或其他底座一起转动，需要补充安装关系，重新转换坐标。六轴 BMI088 的 yaw 是本次上电的相对角度，长时间陀螺漂移也会影响复位精度。

## 中档联动与不回正

左下、中、上档分别使用 `r = 0.5、-1、3`。正常转 C 板时，用连续 yaw 的增量更新目标：

```cpp
target_a += delta_yaw;
target_b += r * delta_yaw;
```

C 板转 60°时，A 转 60°，B 分别转 30°、-60°、180°。联动过程使用连续多圈角度，不对位置误差取最短角，否则会丢失多圈运动。

C 板和两台电机实际停稳后，程序开始检查手动输入。本次修改取消了“两台位置误差都必须小于 0.01 rad”这一入口条件：即使静摩擦等原因使电机停在略有残差的位置，也可以进入手动检测。新的准备条件是 C 板已静止 150 ms、两台速度反馈都小于 0.12 rad/s，且两台实际编码器位置在连续 100 ms 内均保持在 4 格编码器、约 0.176°的窗口内。仍在正常追赶目标时，需要先等实际运动停止。

准备完成时记录两台实测位置作为手动检测起点。之后必须相对该起点产生至少 0.015 rad、约 0.86°的新位移，朝偏离目标的方向移动，并维持 20 ms 才识别。静止时已有的位置残差本身不作为手动输入，也不再要求每个 2 ms 步进超过一个大阈值。本次调整只修复手动检测入口，不改变已调到稳定的 PID 参数。

被拖动的电机作为输入端，输出零力矩。刚识别手动 A/B 时，将该端目标调整为它的实际角度，并把检测前积累的全部偏转按比例补入另一端。持续手动 A 时，两台目标分别加上 `A的完整位移` 和 `r * A的完整位移`；持续手动 B 时，分别加上 `B的完整位移 / r` 和 `B的完整位移`。C 板的 yaw 增量独立保留，避免再次很慢转板时被手动位置更新抵消。

手动输入一旦识别，松手后仍保持该端可回拖，持续读取其完整编码器位移。不会因为速度反馈读成零、或单次编码器变化太小，定时重新上锁并回弹。从端保留完整目标，即使松手时尚未跟完，也会继续完成跟随。

停手 250 ms，且两端实际编码器位置和速度满足上述停稳条件约 100 ms 后，可以拖动另一台电机，将其变成新的输入端；不再要求两台位置误差都小于 0.01 rad。再次转动 C 板时，回到双电机闭环，并从当前位置继续联动。确认 C 板运动后优先使用 C 板输入。

为避免 IMU 噪声立即结束手动输入，退出手动模式需要 yaw 速度超过 0.05 rad/s，或累计偏转超过约 0.176°。低速起步期间的完整 yaw 增量也已保留，确认运动后会一起跟随；但只有小于该阈值的一次缓慢摆动时，被作为手动输入的电机仍保持零力矩，不主动跟随。需要“任意微小动作也立即跟随”时，必须根据真实 IMU 噪声重新调整阈值，当前版本不能作这种保证。

联动参考 yaw 按下面的关系更新，IMU 的实际 yaw 变量不被修改：

```cpp
yaw_reference = actual_yaw - (target_a - angle_A_R);
```

左拨杆切档保留切换时的两台目标位置，后续增量才使用新比例。已经转过的历史角度不会重新缩放。手动模式中切档同样如此。

## 上档复位

上档目标由独立保存的机械标定值计算：

```cpp
R_target_a = angle_A_R + (current_yaw - yaw_R);
R_target_b = angle_B_R + (current_yaw - yaw_R);
```

进入上档时，分别选择与各电机当前角度最接近的等价整圈位置。之后持续跟随连续 yaw，使两个 R 标都朝向 C 板当前 R 标方向。上档不使用左拨杆比例，也不进行手动参考更新。

## 控制参数和上板检查

角度单位为 rad，角速度为 rad/s。本工程的 `RM_Motors::GM6020` 使用电流控制协议，`cmd()` 单位为 N·m，两个电机的发送 ID 都是 `0x1FE`。请确认实际 6020 支持并配置成该模式。若使用 `GM6020_V` 的电压协议，发送 ID 和输出单位会改变，必须同时重新设置增益和输出限幅，不能只改枚举值。

当前固件使用位置 P 外环、速度 PI 内环，两台电机各有一套独立积分状态。速度 Ki 当前为 0.05，目标速度前馈仍关闭。用户已固定两台电机不旋转的外壳，并实机反馈持续抖动消失、C 板带动电机在三个左拨杆比例档位均能正常工作。这个结果适用于当前装置和当前负载，尚未量化最终角度误差；手动拖动不灵敏的问题仍在调查，手动联动及 R 标复位不能据此视为验收通过。控制关系如下：

```cpp
position_error = target_angle - actual_angle;
feedforward_speed = use_feedforward ? filtered_target_speed : 0;
speed_set = clamp(position_Kp * position_error + feedforward_speed, max_speed);
speed_error = speed_set - actual_speed;
I = clamp(I + speed_Ki * speed_error * actual_dt, max_integral);
torque = clamp(speed_Kp * speed_error + I, max_torque);
```

实际代码还包含输出饱和时的条件积分：积分会使饱和加重时停止累积，反向误差可以退积分。积分限幅针对 I 项输出（单位 N·m），不是未乘 Ki 的误差积分。

位置 P 外环输出目标速度，速度内环输出力矩。位置和速度分别闭环。速度内环 I 可以在角度误差很小时继续提供抵消摩擦或恒定负载的保持力矩。稳定、恒定目标/负载且力矩和积分限幅足够时，稳态速度误差应趋零；实际速度为零时，位置 P 所要求的速度也趋零，位置误差随之趋零。传感器偏差、量化、持续饱和或不稳定仍会限制实际精度。之前 Ki 为零的方案只用于诊断稳定性，静摩擦或持续负载导致的位置误差可能更大；当前已恢复小积分，但最终精度仍需测量验收。

位置外环 `Ki = Kd = 0`，速度内环 `Ki = 0.05、Kd = 0`，两环并不需要都同时启用 P、I、D。把位置环和速度环的积分都开大容易增加过冲。GM6020 速度反馈按整 RPM 量化，1 RPM 约为 0.1047 rad/s，直接微分还容易放大台阶噪声，所以当前使用位置 P + 速度 PI，没有加入速度 D。

参数在 `motor_task.cpp` 中统一设置：

| 参数 | 当前值 | 含义 |
| --- | ---: | --- |
| `kPositionKp` | 2.0 | 外环，单位 (rad/s)/rad |
| `kSpeedKp` | 0.04 | 内环，单位 N·m/(rad/s)，保留用户最新保存的调参值 |
| `kSpeedKi` | 0.05 | 速度内环积分，单位 N·m/rad，积分使用实测秒数 |
| `kMaxSpeed` | 1.5 | 目标速度限幅，rad/s |
| `kMaxTorque` | 0.15 | 总力矩限幅，N·m |
| `kMaxIntegral` | 0.05 | I 项输出限幅，N·m |
| `kVelocityFilterTime` | 0.02 | 目标速度前馈滤波时间常数，s |
| `kEnableVelocityFeedforward` | false | 实际电机任务暂关目标速度前馈 |

开启目标速度前馈时，它由目标角度变化计算，先限幅再经 20 ms 滤波，并与外环位置修正共同接受目标速度限幅。`CascadePID` 的构造函数默认支持开启前馈，供已有算法测试使用；实际 A/B 电机任务显式传入 `kEnableVelocityFeedforward = false`，不会使用它。1.5 rad/s 是速度指令的限幅，不是机械转速的硬上限。控制器使用每次循环实测 dt；非有限输入、dt 非正或任务间隔超过 50 ms 时清积分并输出零力矩。

下档、失联、右档模式改变、被选为手动输入、从手动输入恢复闭环时清除对应控制器的积分和前馈状态。手动输入端仍输出零力矩，从端正常运行双环并保留其积分；这样不会把之前积累的保持力矩带到手动状态而造成回弹。识别前仍需要满足准备条件并越过约 0.86°的新位移阈值，过大的增益会让拖动费力。

更换负载、安装或控制参数后，应重新检查转板后的稳定性：固定两台电机不旋转的外壳，让转子旋转，C 板独立转动；无需把电机与 C 板连接。完成标定后，左拨杆下档、右拨杆中档，慢慢转 C 板 5～10°，然后停住 2～3 秒，观察两台能否停止摆动。不稳定时切右下档停止输出，再检查原因。当前装置已由用户反馈稳定，不需要为继续验收而再随意降低增益。

调试器中展开 `motor_debug`，观察 `yaw、target_a/b、angle_a/b、angle_error_a/b、speed_set_a/b、speed_a/b、p_a/b、i_a/b、torque_a/b、dt_ms、manual_motor、manual_ready、manual_candidate、healthy、enabled`。当前 Ki 为 0.05，`i_a/i_b` 可以非零，用于观察保持力矩和积分是否达到 0.05 N·m 的限幅。若以后重新出现抖动，应先记录这些量；需要比较不同参数时，每次只改一个参数，不要同时乱改多个增益或翻转 `Direction`。

如果 C 板已停住，而 `yaw` 或目标仍持续变动，先检查 IMU 输入及联动状态；若目标稳定而实际角度、速度和力矩持续来回变号，则支持继续检查闭环参数、速度反馈、时序和输出协议，但不能仅凭目标稳定断言只剩 PID 问题。`torque_a/b` 是软件请求力矩，不是实测力矩，也不是 CAN 整数量化后的电流值。`healthy/enabled` 反复切换时，还需检查遥控、电机反馈和 IMU 更新是否掉线。速度的整 RPM 量化可能形成台阶，但仅看到台阶也不能确认它就是振荡原因。

若更换装置或负载后需要重新整定，可以暂将速度 Ki 置零检查基础响应，稳定后从 `kSpeedKi = 0.01f` 开始加入小积分，观察静止误差和过冲，再按实测结果逐步调整；最后需要更快跟随时再提高位置 Kp。这是重新整定的方法，不是当前参数状态。速度内环响应应明显快于位置外环，调得过慢的内环配合过快的外环也可能振荡。两台电机负载不同，实际需要时可分别设置参数。当前 Ki 为 0.05 的装置可继续检查最终角度误差、手动输入和复位功能。

这些参数需要在真实负载上调整；编译和纯逻辑测试不能验证机械闭环稳定性。方向参数只用于统一观察方向：同一侧观察时，C 板逆时针转动，A 应同向，左上档 B 也应同向。确认只是观察方向与传感器符号相反后，才调整对应 `kYawDirection`、`kMotorADirection` 或 `kMotorBDirection`。电机方向参数同时作用于反馈和输出；它不会修复电机自身“正力矩使原始编码器角度减小”的反馈符号问题，也不应作为消除抖动的试错开关。

建议按以下顺序实测：

1. 右下档检查两台电机没有主动保持力矩；零命令不能消除机械摩擦和电机齿槽阻力。
2. 先按上述左下、右中、小角度测试调到稳定，再左下/中/上分别让 C 板转 +60°、-60°，观察 A/B 方向及最终位移。
3. 按下面的手动检测流程，慢转 A，再慢转 B；检查另一台的比例、松手不回正、再次转板不回旧位置。
4. 非零位置切左档，检查切档瞬间目标没有跳变。
5. 手动改变两台角度后切右上档，检查 R 标方向对齐；保持上档转 C 板，两台均应按 1:1 更新 R 方向。

手动检测复测时，右拨杆中档，先保持 C 板静止，让两台实际停止运动，再等约 0.5～1 秒，确认 `motor_debug.manual_ready == true`。左下档时慢慢将 A 转动约 10°，保持 C 板不动；识别后应看到 `manual_motor == 1`、`torque_a == 0`，B 的目标增加约 5°。松手后 A 不应被拉回旧位置。等两台重新停稳并准备好，再将 B 转动约 10°；识别后应看到 `manual_motor == 2`、`torque_b == 0`，A 的目标增加约 20°。从 A 换成 B 之前，仍需等待停手 250 ms 和准备条件成立。

`manual_candidate` 用于观察正在确认的候选输入端，0 表示无候选、1 表示 A、2 表示 B；`manual_motor` 使用相同编码。若松手后回旧位置且 `manual_motor` 始终为 0，应先检查准备状态和候选检测，不能直接认定是从端 PID 太慢。`manual_ready == false` 时，单纯继续降低手动位移阈值不能解决准备条件未满足的问题；先看 C 板是否静止、两台编码器位置及速度是否真的停稳，并结合 `angle_error_a/b` 区分静止残差和仍在追赶，不要盲目增加 Ki。新入口允许停稳后的角度残差，不要求误差必须归零。

只有已经确认 `manual_motor == 1/2`、对应输入端软件力矩为零且另一台目标确实按比例变化，另一台仍跟随很慢时，才继续检查从端控制响应。当前用户已反馈“手动松手回原位、另一台跟随慢或有时不动”，本次入口修改仍需按上述流程上板复测，不能宣布手动联动已验收。

拖动识别只能从运动推断外力，仍受编码器分辨率、振动、负载和 IMU 噪声影响。当前设计先等板和两台实际停稳，再允许手动识别，允许停稳后的跟踪残差；它仍不是在任意正常追赶过程中都能无条件识别手动输入。若有这种要求，应增加外力/触碰检测或可靠的扰动观测器。

下档、遥控超时、任一电机反馈超时、IMU 任务超时或非有限角度数据都会发送零力矩。IMU 更新时间仅表示任务发布新姿态，当前 BMI088 驱动不返回每次 SPI 读取成功标志，不能据此检测全部 IMU 硬件故障。
